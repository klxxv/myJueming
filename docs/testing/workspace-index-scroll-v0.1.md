# 双栏滚动索引缓存验证

2026-09-13；针对 macOS 开发版双栏审阅／编辑滚动停顿。

## 原因与实现

此前每次正文 Slice 返回，`App.refreshVisibleRows` 都重新构造两侧全文结构数组，触发 `buildAlignmentBlocks`。其中连续性检查为每个 Alignment 重建全文顺序 Map，普通 1:1 工程也出现平方级遍历。可视区裁剪仍扫描全部块；每张卡片还计算未显示的插入空位按钮，开发版每帧另有全表统计和日志。

现在 `useWorkspaceIndex` 在导入／打开时建立当前工程／文档对的 SegmentId 与 AlignmentId 内存索引。后续 canonical 快照只替换结构改变的条目，保留未变化的对象和数组；新关系加入，解除、Group/Ungroup、内容拆分合并、Undo/Redo/Restore 移除或替换旧条目。结构快照目前仍按版本整体返回，因此每个新版本仍需一次结构比对；并非磁盘上的增量数据库索引。

滚动补入正文只更新相应浅层响应式 Segment 的 `text`／`loaded`；正文淘汰同时清空该对象的文字。缓存保留轻量结构，不把整个工程正文留在内存索引中。对齐连续性检查复用已有 ID Map；可视区从二分查找到的第一个块开始截取；隐藏空位按钮不计算；逐帧布局日志默认关闭，可通过 `VITE_ALIGNMENT_LAYOUT_DEBUG=true` 显式启用。

## 隔离页面对比

环境：本机 macOS 15.5，Intel Xeon E5-2680 v3 2.50 GHz；Playwright WebKit 2336 headless，1440×1000 视口，现有 Vite dev 服务。加载实际 Vue App，使用架构页面回归中的模拟 IPC 与 1:1 短句数据。每个规模首次向下滚动 20 步，每步 48 px，由 `requestAnimationFrame` 驱动，再在同一区域向上滚动 20 步。计时插桩仅在测试浏览器响应中加入，不进入应用源码。

| 对数／区域 | 采样帧间隔中位数：修改前 → 后 | 采样最大间隔：修改前 → 后 | 滚动期间全量投影重建：修改前 → 后 |
| --- | --- | --- | --- |
| 300 对，首次向下 | 164 → 16 ms | 278 → 23 ms | 11 → 0 |
| 300 对，已加载区域向上 | 14 → 14 ms | 28 → 27 ms | 0 → 0 |
| 800 对，首次向下 | 867 → 22 ms | 1049 → 33 ms | 11 → 0 |
| 800 对，已加载区域向上 | 13 → 13 ms | 23 → 26 ms | 0 → 0 |

两版首次向下均请求 11 个 Slice，末端 DOM 均为 52 个句段；返回顶端均为 34 个句段。改动没有通过预加载全部正文或取消虚拟化换取速度。页面均无未捕获异常。

以上为单次短样本、模拟 IPC 的主线程帧调度对比，不是原生触控板 FPS，也不是发布级性能基线。没有测量系统 WKWebView、原生 IPC／磁盘延迟、真实长句／复杂大分组和不同显示器的整体体验。现有可变高度测量和同步滚动锚定仍沿用原实现。
